# Provenance Guard — Planning Document

## Implementation Spec

### 1. Detection Signals

**Signal 1 — Stylometric Heuristics** (local, no API cost)

| Sub-metric | What it measures | AI tendency |
|---|---|---|
| Sentence-length variance | Standard deviation of per-sentence word counts | Lower — AI prose is metronomic |
| Hedge/filler phrase density | Frequency of phrases like "it is worth noting," "furthermore," "in conclusion" per sentence | Higher — RLHF training rewards measured, balanced tone |
| Varied-punctuation density | Rate of `;`, `:`, `—`, `…`, `()` per word | Lower — AI uses fewer stylistic punctuation marks |

Each sub-metric is normalized to [0, 1] where **1.0 = strong AI signal**. The three sub-scores are blended:

```
style_score = 0.40 × slv_score + 0.40 × hedge_score + 0.20 × punct_score
```

Output: a single float `style_score ∈ [0, 1]`.

---

**Signal 2 — LLM Classifier** (Groq API, semantic signal)

Sends the text to `llama-3.1-8b-instant` with a structured system prompt instructing it to return `{"ai_probability": <float>}`. The prompt directs the model to evaluate structural uniformity, transitional templates, hollow specificity, and absence of genuine personal voice.

Output: a single float `llm_score ∈ [0, 1]`.

---

**Combining signals into `ai_probability` and `confidence`:**

```
ai_probability = 0.40 × style_score + 0.60 × llm_score
confidence     = 1.0 − |style_score − llm_score|
```

The LLM signal receives more weight (0.60) because it captures higher-level semantic patterns that stylometrics cannot reach. `confidence` is not a second opinion on the probability — it measures *signal agreement*. When both signals point the same direction, confidence is high. When they diverge, confidence falls toward 0.

---

### 2. Uncertainty Representation

**What `confidence` means concretely:**

| confidence value | interpretation |
|---|---|
| 0.90 – 1.00 | Both signals strongly agree. Label is definitive. |
| 0.70 – 0.89 | Signals mostly agree. Label is `ai_high` or `human_high`. |
| < 0.70 | Signals disagree meaningfully. Label is **always `uncertain`**, regardless of `ai_probability`. |

**What a score of 0.60 means:** The two signals differ by 0.40 (e.g., `style_score = 0.30`, `llm_score = 0.70`). The system cannot tell whether the stylometric signal is failing (polished human prose that looks uniform) or the LLM signal is failing (AI text that was edited). At confidence 0.60, the `uncertain` label fires and the creator is invited to appeal. The system does not guess.

**Threshold table:**

| condition | label variant |
|---|---|
| `confidence < 0.70` | `uncertain` |
| `confidence ≥ 0.70` AND `ai_probability > 0.55` | `ai_high` |
| `confidence ≥ 0.70` AND `ai_probability ≤ 0.55` | `human_high` |

**Calibration approach:** The 0.55 AI threshold is set below 0.5 to bias toward false negatives (labelling AI content as uncertain) rather than false positives (labelling human content as AI). This reflects the asymmetric cost: incorrectly flagging a human creator causes more harm than failing to catch AI content.

---

### 3. Transparency Label Variants

These are the exact strings the system returns in `label_text`. `{X}` is replaced with `round(ai_probability * 100)`.

**`ai_high`** (confidence ≥ 0.70, ai_probability > 0.55):
> "Our analysis suggests this content was likely generated by AI (AI probability: {X}%). We detected consistent patterns associated with AI writing across multiple signals."

**`human_high`** (confidence ≥ 0.70, ai_probability ≤ 0.55):
> "Our analysis suggests this content was likely written by a human (AI probability: {X}%). Multiple signals found characteristics consistent with human authorship."

**`uncertain`** (confidence < 0.70):
> "We couldn't confidently determine whether this content is human-written or AI-generated (AI probability: {X}%). Our signals gave mixed results. If you wrote this yourself, you can file an appeal below."

---

### 4. Appeals Workflow

**Who can appeal:** Any creator who has a valid `content_id` from a prior `/submit` response. No authentication is required in this version; `creator_id` is an optional self-reported string.

**What they provide:** `content_id` (required), `reason` (required, 10–1,000 characters), `creator_id` (optional).

**What the system does on receipt:**
1. Validates that `content_id` exists in the audit log. Returns 404 if not found.
2. Attaches an `appeal` object to the existing log entry: `{ appeal_timestamp, creator_id, reason }`.
3. Sets `status` from `"decided"` → `"under_review"`.
4. Returns confirmation to the creator. No automated re-classification occurs.

**What a human reviewer sees when opening the appeal queue (`GET /log`):**

Each entry with `status: "under_review"` contains the full original decision alongside the appeal:

```json
{
  "content_id": "...",
  "timestamp": "2025-01-01T12:00:00Z",
  "ai_probability": 0.72,
  "confidence": 0.61,
  "style_score": 0.68,
  "llm_score": 0.74,
  "label_variant": "uncertain",
  "status": "under_review",
  "appeal": {
    "appeal_timestamp": "2025-01-01T12:05:00Z",
    "creator_id": "poet_user_123",
    "reason": "This is my original work. I can provide handwritten drafts."
  }
}
```

The reviewer can see the raw signal scores that drove the decision, the label that was shown, and the creator's stated reason — all in one record.

### 5. Anticipated Edge Cases

**Edge case 1 — Formally structured poetry (false positive risk)**

A Petrarchan sonnet uses rigid metrical structure: 14 lines, very similar syllable counts per line, formal diction, no sentence fragments, no conversational punctuation. Signal 1 will score this high on `slv_score` (uniform line lengths) and possibly on `punct_score` (few parentheses or dashes). Signal 2 may also score it high because the formal transitional phrases and balanced structure resemble LLM output patterns. The system's response: if the two signals agree, it may incorrectly issue `ai_high`. The confidence gate partially mitigates this — a poet who writes very variably within the sonnet form will produce signal disagreement — but it is not a reliable safeguard for highly regular forms (sonnets, villanelles, ghazals).

**Edge case 2 — AI-generated text that was lightly edited by a human (false negative risk)**

A creator uses an LLM to draft a blog post, then edits it for personal voice: breaks a few long sentences, adds a personal anecdote, swaps some hedge phrases for colloquial language. The edits disrupt the uniform sentence-length signal (Signal 1 scores drop toward neutral). Signal 2 may still catch the underlying AI structure, but if the edits were thorough enough, the signals diverge and confidence drops below 0.70, producing `uncertain` rather than `ai_high`. The system cannot distinguish "genuinely human but formal" from "AI-drafted but edited." This is a fundamental limitation of any signal-based approach that does not have access to the generation process itself.

## Architecture Narrative

A single piece of text travels through the system as follows:

1. **Creator submits** text via `POST /submit`. The request body includes the raw content and an optional creator ID. The endpoint validates the input (non-empty, within length limits) and generates a unique `content_id` (UUID).

2. **Signal 1 — Stylometric heuristics** runs first. This is a local, deterministic pass over the text. It computes lexical diversity (type-token ratio), sentence-length variance, and the density of hedging/filler phrases. These three sub-metrics are combined into a single `style_score` in [0, 1] where 1.0 = strong AI signal.

3. **Signal 2 — LLM Classifier** runs next. The raw text is sent to an LLM (via Groq) with a carefully crafted prompt that asks it to evaluate whether the passage was likely AI-generated. The LLM returns a probability estimate. This becomes `llm_score` in [0, 1].

4. **Confidence Scorer** combines the two signals using a weighted average (`style_score * 0.4 + llm_score * 0.6`). The LLM signal gets more weight because it captures higher-level semantic patterns that stylometrics miss. The combined value is the raw `ai_probability`. A second value, `confidence`, measures how much the two signals *agree* — high agreement → high confidence; disagreement → the label degrades to "uncertain" regardless of the raw probability.

5. **Transparency Label Generator** maps `(ai_probability, confidence)` to one of three label variants. If confidence is low (< 0.70), the label is always "uncertain." Above that threshold, high ai_probability → AI label, low → human label.

6. **Audit Logger** writes a structured JSON record to the append-only log. The record includes: `content_id`, `timestamp`, `ai_probability`, `confidence`, `style_score`, `llm_score`, `label_variant`, and `status` (initially `"decided"`).

7. **Response** is returned to the caller: `content_id`, `label_variant`, `label_text`, `ai_probability`, `confidence`, and both raw signal scores.

## Detection Signals

### Signal 1 — Stylometric heuristics

**What it measures:**
- **Lexical diversity** (type-token ratio): unique words ÷ total words. AI tends to produce higher raw diversity but with less contextual richness.
- **Sentence-length variance**: standard deviation of per-sentence word counts. Human writing is irregular; AI prose is noticeably uniform.
- **Hedge/filler density**: frequency of phrases like "it is worth noting," "in conclusion," "it is important to," "as mentioned." These are overrepresented in LLM output.

**Why these properties differ between human and AI writing:**
AI models are trained to produce fluent, coherent prose. Fluency is rewarded during training; statistical regularity is a side effect. Humans write with natural rhythm variation — they go on tangents, use fragments, vary pace. AI writing tends to be metronomic. Hedge phrases are overrepresented because LLMs are RLHF-trained to sound measured and balanced.

**Blind spots:**
- Professional, edited human writing (grant proposals, news articles, legal documents) scores high for uniformity and low lexical variety — may trigger false AI flags.
- AI content that's been lightly edited by a human will disrupt the uniform sentence length signal.
- Short texts (< 100 words) give unreliable variance estimates.

---

### Signal 2 — LLM Classifier (Groq)

**What it measures:**
Semantic and stylistic patterns that another LLM can recognize as characteristic of AI generation: over-structured paragraphs, certain transitional templates, absence of genuine personal voice, suspiciously balanced "on one hand / on the other hand" structures, and surface fluency with hollow specificity.

**Why these properties differ:**
LLMs are uniquely good at recognizing their own family's output distributions. The classifier prompt asks the model to reason about patterns it knows from its own training, making this a form of self-knowledge applied externally.

**Blind spots:**
- Circular reasoning risk: the LLM may flag any smooth text, not just AI text.
- Prompt injection: a sophisticated adversary could include text that manipulates the classifier's reasoning.
- The LLM's knowledge reflects its training distribution — novel AI models or heavily fine-tuned outputs may fool it.
- This signal has API cost and latency; it cannot run offline.

## False-Positive Trace: Misclassifying a Human Writer

**Scenario:** A poet submits a formally structured sonnet — metrically regular, highly polished, using literary hedges ("Perhaps," "It seems"). Signal 1 gives a high AI score (uniform sentence lengths, low variance). Signal 2 also scores it moderately high (formal structure, balanced phrasing). Combined `ai_probability` = 0.72, but the two signals only partially agree, so `confidence` = 0.61.

**How the system responds:**
- Because `confidence` < 0.70, the label generator falls back to **"uncertain"** regardless of the 0.72 probability.
- The transparency label text reads: *"We couldn't confidently determine whether this content is human-written or AI-generated. Our signals gave mixed results. If you wrote this yourself, you can file an appeal below."*
- The audit log records the event with `label_variant: "uncertain"`, `status: "decided"`.

**Appeal path:**
- The poet sees the label and clicks "Appeal."
- They submit a POST /appeal with their `content_id` and a short statement: *"This is my original work. I can provide my draft notes."*
- The system logs the appeal (adds an `appeal_record` to the audit entry), sets `status` to `"under_review"`, and returns confirmation.
- A human moderator reviews the case; the audit log is the canonical record they read.

**What this tells us about design choices:**
- The confidence gate prevents a single ambiguous signal from issuing a definitive AI label unfairly.
- The appeal captures creator voice and attaches it to the same `content_id` — moderators have full context.
- Uncertainty is communicated to users honestly, not hidden behind false precision.

## API Surface

### POST /submit
Accepts a content submission for attribution analysis.

**Request body:**
```json
{
  "content": "string (required, 50–10000 chars)",
  "creator_id": "string (optional)"
}
```

**Response:**
```json
{
  "content_id": "uuid",
  "label_variant": "ai_high | human_high | uncertain",
  "label_text": "string (the exact text shown to users)",
  "ai_probability": 0.72,
  "confidence": 0.61,
  "signals": {
    "style_score": 0.68,
    "llm_score": 0.74
  },
  "status": "decided"
}
```

**Rate limit:** 10 requests / minute per IP.

---

### POST /appeal
Allows a creator to contest a classification.

**Request body:**
```json
{
  "content_id": "uuid (required)",
  "creator_id": "string (optional)",
  "reason": "string (required, 10–1000 chars)"
}
```

**Response:**
```json
{
  "content_id": "uuid",
  "status": "under_review",
  "message": "Your appeal has been logged. A moderator will review it."
}
```

**Rate limit:** 5 requests / hour per IP.

---

### GET /log
Returns the structured audit log.

**Query params:** `limit` (default 50), `offset` (default 0).

**Response:**

{
  "entries": [

## Architecture

In the **submission flow**, a creator's text enters the API, passes through two independent signals (stylometric heuristics locally, then an LLM classifier via Groq), and the resulting scores are combined into an `ai_probability` and a `confidence` value; the confidence gate then selects one of three transparency label variants, the full decision is written to the append-only audit log, and the structured response is returned to the caller. In the **appeal flow**, a creator submits their `content_id` and a written reason; the system looks up the existing log entry, attaches the appeal record, flips the status to `"under_review"`, and confirms receipt — no re-classification happens automatically, leaving the final call to a human moderator who reads the original signal scores and the creator's statement side by side in the log.

### Submission Flow

```
Creator
  │
  │  POST /submit  { content, creator_id }
  ▼
┌─────────────────────────┐
│   Flask API Layer       │  ← rate limiter (10 req/min/IP)
│   Input Validation      │
│   content_id = UUID     │
└────────────┬────────────┘
             │ raw text
             ▼
┌─────────────────────────┐
│  Signal 1               │
│  Stylometric heuristics   │  ← lexical diversity
│  (local, deterministic) │    sentence-length variance
│                         │    hedge/filler density
└────────────┬────────────┘
             │ style_score [0,1]
             ▼
┌─────────────────────────┐
│  Signal 2               │
│  LLM Classifier (Groq)  │  ← prompt + raw text → LLM
│                         │    LLM returns probability
└────────────┬────────────┘
             │ llm_score [0,1]
             ▼
┌─────────────────────────┐
│  Confidence Scorer      │  ← ai_probability = 0.4*style + 0.6*llm
│                         │    confidence = 1 - |style - llm|
└────────────┬────────────┘
             │ (ai_probability, confidence)
             ▼
┌─────────────────────────┐
│  Transparency Label     │  ← if confidence < 0.70 → "uncertain"
│  Generator              │    else ai_prob > 0.55 → "ai_high"
│                         │    else → "human_high"
└────────────┬────────────┘
             │ (label_variant, label_text)
             ▼
┌─────────────────────────┐
│  Audit Logger           │  ← append JSON record to audit_log.jsonl
│  (append-only .jsonl)   │
└────────────┬────────────┘
             │ structured response
             ▼
          Creator
   { content_id, label_variant, label_text,
     ai_probability, confidence, signals }
```

### Appeal Flow

```
Creator
  │
  │  POST /appeal  { content_id, reason }
  ▼
┌─────────────────────────┐
│   Flask API Layer       │  ← rate limiter (5 req/hr/IP)
│   Validate content_id   │    reject if content_id unknown
│   exists in log         │
└────────────┬────────────┘
             │ appeal record
             ▼
┌─────────────────────────┐
│  Appeal Handler         │  ← load existing log entry
│                         │    attach { appeal_timestamp, reason }
│                         │    update status → "under_review"
└────────────┬────────────┘
             │ updated record
             ▼
┌─────────────────────────┐
│  Audit Logger           │  ← overwrite/append updated entry
│  (append-only .jsonl)   │    with appeal fields + new status
└────────────┬────────────┘
             │
             ▼
          Creator
   { content_id, status: "under_review", message }
```

## Rate Limiting Decisions

| Endpoint | Limit | Reasoning |
|---|---|---|
| POST /submit | 10 / minute / IP | Each submission triggers a paid LLM API call (Groq). At 10 req/min, a single abusive IP costs ~$0.006/min at current Groq pricing — manageable. Legitimate creative platforms submit content far less frequently. |
| POST /appeal | 5 / hour / IP | Appeals require moderator time. Unlimited appeals would enable DoS on the moderation queue. 5/hr gives creators room to contest multiple works without enabling spam. |
| GET /log | 60 / minute / IP | Read-only; low cost. Higher limit to support dashboards and monitoring. |
